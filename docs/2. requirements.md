Product Requirements Document (PRD)

Project Name: CogniShell
Phase: 1 (MVP)

1. Overview

CogniShell is a centralized, AI-augmented automation engine. This document outlines the Phase 1 requirements, breaking down the features defined in idea.md into Agile Epics and User Stories.

2. Technology Stack Definition

Backend: Go (Golang)

Frontend: Next.js (React / TypeScript)

Datastore (Metrics): PostgreSQL

Datastore (Logs): Grafana Loki

Observability: Prometheus & Grafana

Secrets Management: HashiCorp Vault

AI Orchestration: Ollama (Self-hosted)

3. Agile Epics & User Stories

Epic 1: Core Execution Engine & GitHub Integration

Objective: Build the foundational server capable of fetching and executing PowerShell scripts securely.

Story 1.1: As an execution engine, I need to expose a REST API endpoint /api/v1/execute that accepts a script name, branch, and target server parameters.

Story 1.2: As an execution engine, I need to dynamically fetch the requested .ps1 script from the connected GitHub repository using the GitHub REST API (Octokit/Go-GitHub) without saving it to disk.

Story 1.3: As an execution engine, I need to spawn an isolated pwsh (PowerShell Core) process, pipe the fetched script into it, and capture stdout, stderr, and the ExitCode.

Epic 2: Security & Identity (HashiCorp Vault)

Objective: Ensure no secrets are hardcoded by integrating dynamic credential fetching.

Story 2.1: As the execution engine, before running a script, I need to authenticate with HashiCorp Vault using an AppRole or JWT.

Story 2.2: As the execution engine, I need to fetch the target environment's "Functional ID" credentials from Vault and pass them securely into the PowerShell process (via secure environment variables or a PSCredential object).

Epic 3: Observability & Telemetry

Objective: Track the health, performance, and output of every script execution.

Story 3.1: As a telemetry module, I need to push the raw execution logs (stdout/stderr) to Grafana Loki, tagged with the ExecutionID and ScriptName.

Story 3.2: As a telemetry module, I need to expose a /metrics endpoint for Prometheus that tracks script_duration_seconds, script_success_total, and script_failure_total.

Story 3.3: As an administrator, I need a scheduled job that purges logs from Loki/PostgreSQL older than 30 days to manage storage costs.

Epic 4: AI-Driven Auto-Remediation

Objective: Use self-hosted LLMs to automatically triage and report script failures.

Story 4.1: As the execution engine, if a script exits with a non-zero code, I need to package the stderr trace and the script source code into a JSON payload.

Story 4.2: As the AI module, I need to send the failure payload to the internal Ollama server with a strict prompt asking for bug analysis and remediation steps.

Story 4.3: As the GitHub integration module, I need to automatically open a GitHub Issue in the source repository containing the LLM's analysis and the error logs.

Story 4.4: As an alerting module, I need to parse the repository's CODEOWNERS file to assign the GitHub issue and send a webhook notification to the team's Slack/Microsoft Teams channel.

Epic 5: Developer UI / Portal

Objective: Provide a read-only pane of glass for developers to view available automation.

Story 5.1: As a developer, I need a web dashboard (Next.js) that lists all "Production Ready" scripts currently residing in the main branch of the GitHub repository.

Story 5.2: As a developer, when I click on a script, I want to see its README.md rendered cleanly in Markdown format.

Story 5.3: As a developer, I want to see an embedded Grafana panel on the script's page showing its 30-day success/failure ratio and average execution time.

4. Phase 1 Success Criteria

A script can be triggered via an API call.

The script runs on a target server using Vault credentials, leaving no local trace.

Successful runs are visible in Grafana.

Failed runs automatically generate a detailed, AI-analyzed GitHub issue and a Slack/Teams alert within 60 seconds of failure.
